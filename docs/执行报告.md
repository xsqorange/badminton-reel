### 3.7 附带澄清:`encode.vsync: "cfr"` 的语义(裁定 D1)

base.yaml 只增不改的前提下,**`encode.vsync` 的值一个字都没动**(仍是 `"cfr"`),
只在那一行上面补了注释:

> fps 滤镜已做 CFR 重采样(eliminate -vsync VFR),这里的 `-vsync cfr`
> 只作用在滤镜输出流上,两者不冲突。

为什么不用改它:源素材是 **VFR 变帧率**,`fps` 滤镜已按时间戳等距重采样,

不改变时间戳(质检实测时间戳 std **0.000ms**、中位 16.667ms)。
所以它与 fps 滤镜**不冲突,语义澄清即可** —— 动了它就会让 10/31、11/01 的
字节级归档基线作废。

## 四、人工逐拍真值(GT 怎么来的)

### 4.1 方法(口径 D:人工目视判定)

1. **候选击球时刻**由独立音频包络法给出(6ms 窗 / 2ms 步 → 局部极大值 →
   相对本段中位数 ≥ +11dB;0.30s 内相邻瞬态按「拍+球」双响规则合并为一次候选)。
   该链与 `src/detect_hits.py` 的 rise / offset / thresh **没有任何共享参数** ——
   **GT 不由检测器输出反推**(A4 纪律)。
2. 每个候选时刻抽 1 帧**主球场 ROI**(4fps 网格,±0.125s),拼成复核表。
3. 人眼逐格判定:前景主球场这一拍有没有**击球动作**(挥拍出手 / 弓步 / 扑救 / 球在空中)。
   有 → 记 1 拍;站立持拍、走动、弯腰捡球 → 记 0 拍。
4. `shots` = 判定为真的候选数。

工具:`tools/gt_review_sheet.py`;复核表:`work/sheets/gtreview/<id>.png`。
方法论规则已写进 `docs/标注规范.md` 第九节:
**判定「是不是一回合」必须按候选瞬态时刻抽帧,不能按固定间隔抽帧**
(固定间隔会落在等球间隙上,把真回合误判成「不是回合」,也会把「站着不动」误判成「在打」)。

## 五、门控调参与回合合并(数据)

  「未判定」≠「判定为否」:此处不写条数,等 E1 帧串判定落地后回填。

**说明(口径优先级)**:本节是**三套口径的对照与冲突清单**(用来解释历史数字为什么打架),
**不是拍数裁定**。按终裁,拍数以 **C3 裁定表**(E1 帧串判定)为准 —— 该表**尚未落地**,

"两个可交叉验证的口径不一致、且区间跨越 30"这个事实本身。
